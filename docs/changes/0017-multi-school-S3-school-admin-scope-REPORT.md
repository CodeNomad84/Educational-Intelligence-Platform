## SECURITY REVIEWS (static, all findings; one fix round per commit; Medium+ NOT fixed, left to the owner)
**MEDIUM — YOUR DECISION (Tier C):**
- **S3-2 F6 (gate design):** with S3 live, `compare_access_parity --multi-school` can never pass in a genuine multi-school deployment: `students_lost/grades_lost/attendances_lost` count every row an admin's membership scope hides, i.e. the other schools' rows by design (run above). It also recomputes the scope arithmetically instead of calling `visible_*`, its wording says "today = everything", and the default (non-multi-school) mode compares `access_legacy`, which still returns everything for SchoolAdmin, so admins combined with another role show UNEXPLAINED differences. Needs a decision: redefine the parity gate (e.g. compare the real `visible_*` with an independent expected set per admin, lost-rows only INFO) before it is used as the S3 acceptance gate.
- **S3-2 F1 / S3-3 F2 (`demo_intel`, demo settings only):** its views read all students for any SchoolAdmin (your decision 3: unscoped). Recorded as CURRENT RISK; `school_dashboard` is returned before the scoped aggregates in demo mode.
- **S3-2 F2 (FastAPI / library):** the service token carries `roles_for(user)`, so a membership-less or PlatformAdmin+SchoolAdmin account (and a superuser) is `SchoolAdmin` for FastAPI and the document library, which has no school concept: library list/upload/delete is NOT school-scoped. CURRENT RISK until S5 and a school attribute on documents.
- **S3-3 F1 (import race, = the S4(a) requirement of 0010):** two importers of different schools with the same new national id at once can overwrite each other's row (PostgreSQL: the row lock on zero rows locks nothing; the post-write check sees the overwritten object). Pre-existing check-then-write, now with a real second school possible; fix = conditional write + concurrency test (S4(a)).
- **S3-1 F1:** the 4c producer pre-fills every declared key with 0, so the runtime "missing counter" check cannot fire for the real producer (the source test and per-key tests do guard); also the default output now always carries all 7 info keys (F2, additive). Recommend: build the dict without pre-fill like `readiness_counts`.
**Low/Info, fixed in the review rounds:** pins for the 4c tuples (S3-1 F4), `import_store` exemption list and `school_id` filters (S3-3 F6), non-ASCII signature crash (S3-4 F1), domain-separated HMAC key (F3), clean error for an unserialisable payload (F4).
**Low/Info, recorded NOT fixed:** S3-2 F3 `national_id` existence oracle on API create (global uniqueness until S7); F4 dormant memberships become live when a user is added to the group (audit tool only); F5 deactivated schools still readable; F7 about 9 role/group queries per `features`/`predict` request; F8 Django admin unscoped (S9); F9 legacy NULL-school rows (none since S6); F10 H1 pin blind spots (`fastapi_core`, dotted `get_model` forms). S3-3 F3/F4 refused rows still feed class counters; F5 aggregates are the union of all of an admin's grants; F7 raw exception text returned by the import (pre-existing). S3-4 F2: **R-a is PARTLY done** — the signature stops hand-edited batches, but per-row provenance (created_at/updated_at or hash) is not recorded, so an old valid batch replayed after later legitimate edits still acts on rows whose id/school match; F5 `sign()` is callable by anyone with shell access; F6 R-b covers classes and academic years only (confirm the scope list).

## Follow-up 2026-10-23 (owner decisions on this report; Tier C, one fix round)
- **F6 DONE:** `compare_access_parity --multi-school` is now a strict check. For every account of group SchoolAdmin it computes an independent expectation (one membership join, not `school_ids_for_admin`, row schools read from the row maps) and compares it with the real `visible_students/grades/attendances`: a row outside the member schools = `*_leaked` (FAIL), an expected row missing = `*_locked_out` (FAIL), other schools' rows hidden = `info_other_school_*_hidden` (INFO). An account that also holds Teacher/GradeLead/Parent has its leak check skipped (counted) because it legitimately sees more; the lockout check still runs. Superusers are checked separately (`superuser_scope_wrong`: active = every row, inactive = none). The old `students_lost/grades_lost/attendances_lost` and `explained_by_*` counters are gone. The default (non-multi-school) mode no longer compares SchoolAdmin/superuser accounts with `access_legacy`; it reports them as `school_admin_accounts_not_compared`.
- **S3-1 F1 DONE:** the 4c producer has no pre-filled defaults; each declared key is one literal `report['<key>'] = r['<key>']`, read by `test_the_report_has_no_prefilled_defaults_and_one_literal_assignment_per_declared_key`.
- Recorded in 0010: no second real School before S4(a) and S5; R-a per-row provenance required before any real data.

### /security-review of the F6 commit (`492e8f2`): findings left to the owner (no fix applied; Medium+ is Tier C)
- **M1 (Medium):** `strict_scope_comparison` skips the leak check for a SchoolAdmin who also holds Teacher/GradeLead/Parent; a broken admin branch could leak other schools' rows for such an account and the gate would pass (only the INFO counter `users_with_other_grants_leak_check_skipped` shows it). Likely in practice (first administrators are often teachers). Recommendation: compute the expectation as admin-school rows plus the other grants independently, or evaluate the admin branch in isolation; at minimum make a non-zero skipped count a problem key.
- **M2 (Medium):** the default mode no longer compares SchoolAdmin/superuser accounts with `access_legacy`, which also drops the Teacher/GradeLead/Parent part of dual-role accounts from the 4c parity; `school_admin_accounts_not_compared` is informational. Recommendation: exclude only the admin contribution (compare the non-admin grants), or make a non-zero count for accounts with another role block the gate.
- **Low:** L1 the expectation is independent in code but repeats the rules of `school_ids_for_admin` (a shared wrong rule passes; `memberships_invalid` partly covers it); L2 an inactive superuser holding another role is not leak-checked; L3 the leak check is vacuous with one school or no other-school rows (consistent with the hard gate; a `leak_check_exercised` INFO flag would make it visible).
