# 0020 — S7: what is a person across schools? (CHANGE PROPOSAL, Tier C — the owner decides; nothing is implemented)

**DECISION (owner, 2026-10-26): option C now. S7 = C until a second real school or a first transfer case is planned; then A with a username rule. S8-S10 are deferred until after P3.**

**Question.** `Student.national_id` is globally unique (`students/models.py`, since `0001`). When a student moves from school A to school B, is that one identity or two records?
**What the code does today.** The id is a unique key and also the login name: a student account's username is the student's id, a parent's is the father's (else the mother's) id (`dashboard/bulk_accounts.py`). An import or a bulk-accounts row whose id belongs to another school is refused with one generic message (no disclosure). Consequence: **a transferring student cannot be enrolled in the new school while the old record exists.** A parent with children in two schools is not supported.

| | A. Unique per school | B. Global Person + per-school Student | C. Keep global uniqueness |
|---|---|---|---|
| Data model | `UniqueConstraint(school, national_id)` replaces `unique=True` on `Student`; two independent rows | new `Person(national_id unique)`; `Student(person, school)` unique together; name/identity on Person, school data on Student | nothing changes; document the limitation |
| Existing DBs | one `AlterField`/constraint migration; **irreversible-ish** once a second school holds the same id (restoring global uniqueness then fails). Safe to apply while no id is duplicated | additive table + nullable FK + backfill (one Person per existing Student), later NOT NULL: larger and also irreversible-ish; every applied migration stays untouched in all options | none |
| Accounts / usernames | collision: username = id. Needs a rule, e.g. `<id>` if free else `<id>.<school code>` for the second account (decision), and bulk-accounts must stop treating "id of another school" as an error | one User per Person; a student sees every school's record of themself through one login (Student role currently means "own record": it would span schools) | unchanged: one id = one account = one school |
| Privacy between schools | no disclosure if lookups stay scoped (they are: `import_store`, `visible_*`); the two rows share only a number | Person is a cross-school object: any bug exposes "this person exists elsewhere" and shared fields (name); needs its own access rules and audit | strongest: school B learns nothing, but it is also told nothing useful (generic refusal) |
| `access.py` and the strict gates | `visible_students` unchanged (already school-scoped); `check_student_school_ready`/`check_access_switch_ready` need a duplicate-id counter; import lookups switch to `(school, national_id)` as `0010` §7 already specifies | new join in every student query; the gates and the choke-point guard test need re-doing | none |
| Test impact | modest: import, bulk accounts, usernames, parity/ready checks, the S7 cases in `0010` §10 | large: new model in every fixture, new cross-school leak suite | none |
| Effort | small–medium | large | none |
| Transfer | new row in B; A's history stays in A, nothing is copied (matches "periods are never blended") | one identity, history stays per school, shared view possible later | **blocked** until A deletes or moves the record |

**Recommendation.** Do not start S7 until a second real school is actually planned. Until then keep **C** (zero risk; the RUNBOOK rule already forbids a second real school). When the second school or the first transfer case arrives, choose **A** with an explicit username rule for the second account: it unblocks transfers with the least new cross-school surface, and keeps "no school can learn about another". Choose **B** only if the platform later needs shared history or a single login for one person across schools; that is a product decision with a larger privacy surface.
**Decisions for the owner.** (1) A, B or C, and when. (2) For A: the username rule for a second account of the same id, and whether a parent may have children in two schools. (3) Whether a transfer copies anything (default: nothing).
**Prerequisites in all cases.** Duplicate-id dry run on a copy of synthetic data (`0010` S7 line), live import lookups scoped by `(school, national_id)`, S8–S10 not needed for S7 itself but needed before a second real school. Tier C, owner sign-off, `/security-review`.
